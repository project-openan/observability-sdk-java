# 信号目录

SDK 内置观测信号按 Workflow、A2A-T、Agent 三类分章汇总；每章内按 Metric、Trace、Log 三种信号类型分表。信号属性拆分为独立单元行，逐项给出类型、取值范围与含义。由这些信号递进派生的业务指标及其来源另见《[业务指标视图](业务指标视图.md)》。

注：A2A-T 的 16 个 Trace 均为 A2A 协议操作 Span（与 a2a-java 源码一致，含 `SubscribeToTask-event` / `SubscribeToTask-end`，`SendPushNotification` 仅服务端记录）。

**约定**：

- 每个信号的属性行列出其白名单全集；必填属性缺失、传入白名单外属性或类型不匹配时，该条信号被 SDK 拒绝并输出诊断日志（不含业务值）。
- 属性行首列（信号 / 来源等）为空表示沿用上一行所属信号。
- "来源"列标注信号定义来源：**gen_ai**＝OTel GenAI 语义约定标准信号（`gen_ai.*`）；**a2a**＝A2A 协议信号（YAML 中标记 `protocol: a2a` 的指标与 16 个 A2A 协议操作 Span）；**自定义**＝本项目扩展信号（`gen_ai.agent.a2at.*` 指标、日志事件与 Span）。
- 16 个 A2A 协议操作 Span 与 a2a-java 实现一致：`GetExtendedAgentCard` 仅客户端记录；`SendPushNotification` 仅服务端记录（服务端出站推送调用，Span Kind 为 CLIENT）；其余操作客户端 / 服务端两侧各记录一侧。流式（`SendStreamingMessage`）与订阅（`SubscribeToTask`）调用在两侧均产生 `-event` / `-end` 后缀 Span，二者为独立根 Span，以 Span Link 关联发起方。
- 除 `extension.name`（YAML 枚举强约束）外，字符串属性仅校验非空与类型；"取值范围"列为推荐约定词表。
- API 调用使用属性短名，导出时映射为 YAML 声明的 OTel 全名（前缀 `gen_ai.agent.a2at.`、`gen_ai.agent.a2a.` 或 `gen_ai.`，`error.type` 除外）。
- Trace Span 名称与 Log 事件名称为最终导出名称，导出时原样使用，无 OTel 名称映射（与 A2A 协议 Span 一致）。
- `workflow.step.status` / `substep.status` 在 **Metric 维度**中约定为终态 `success` / `failed`，在 **Trace / Log** 中为运行态（`active`、`running`、`completed`）。
- 属性集完全相同的信号以「同…」引用，不重复罗列：「A2A 通用 Span 属性」＝`SendMessage` 的 22 项白名单；「A2A 事件 Span 属性」＝通用 21 项（不含 `push_notification.event_kind`）＋ 5 项事件属性，共 26 项。
